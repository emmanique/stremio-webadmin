# Stremio Server WebAdmin 2.0.18

## Summary

Maintenance and distribution release that keeps upstream/core 1.6.15 while restructuring how the fork is installed, upgraded, tested and released. The runtime/application feature baseline remains compatible with 2.0.17; the major changes are deployment hygiene, generic host configuration, branch governance and regression/release automation.

## Components

- Fork platform: 2.0.18
- WebAdmin: 2.0.18
- VPN gateway: 2.0.18
- Integrated server/core: 1.6.15

## Changes

- Added a minimal deployment ZIP/TAR generated from the source repository.
- Added pre-upgrade backup of local configuration and persistent state.
- Removed environment-specific defaults from the generic installation template.
- Updated `start.sh` so exported variables override literal `.env` values and automatic host/GPU detection remains safe.
- Standardised long-lived branches on `main` and `development`.
- Split Fast CI, dependency validation, Full regression, release preparation, publishing and controlled upstream integration.
- Made new workflows self-contained with runner-native tooling to avoid zero-job GitHub Actions startup failures.
- Added documentation/change contracts so runtime/configuration changes must update installation and upgrade guidance.

## Validation

- Dependencies workflow: passed on `development`.
- Fast CI: deterministic regression, repository contract and Compose validation passed on `development`.
- Full regression is mandatory on the release PR before merge to `main`; it includes deterministic tests, integration tests, Server/WebAdmin/VPN image builds, runtime smoke tests and deployment-package validation.
- Release publication repeats the same full-regression script before images or deployment artefacts are published.

## Upgrade notes

1. Run `sh scripts/backup-before-upgrade.sh` on the existing installation.
2. Preserve the existing local `.env` and Docker volumes.
3. Extract the 2.0.18 deployment package over the installation directory.
4. Compare `.env` with the new `.env.example` and reconcile newly introduced/renamed variables manually.
5. Run `sh start.sh config` before starting the updated stack.
6. Run `sh start.sh`.
7. Do not use `docker compose down -v` for a routine upgrade.

For a brand-new installation, create `.env` from `.env.example` and review timezone, Pi-hole password, LAN CIDRs, IP detection mode and optional GPU settings before the first start.
