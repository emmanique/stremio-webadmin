# Stremio Server WebAdmin 2.0.0

## Major release

Version 2.0.0 introduces a unified runtime and release model. Direct and VPN operation now use the same Docker Compose topology instead of separate direct and VPN stacks.

## Components

- Core: 2.0.0
- Server/Fork: 2.0.0
- WebAdmin: 2.0.0
- VPN gateway: 2.0.0

## Main changes

- One authoritative `compose.yaml` for Server, WebAdmin, Pi-hole and Gluetun.
- Removed `compose.vpn.yaml`.
- Gluetun remains present as the stable network namespace in both DIRECT and VPN modes.
- VPN activation is a runtime state, not a second Docker deployment.
- Fresh installations work without VPN credentials and start in DIRECT mode.
- VPN can be configured and enabled later from WebAdmin.
- VPN state is persisted in the private `vpn-data` volume.
- VPN profile changes restart the tunnel process without restarting the gateway container.
- Stremio configuration persistence remains independent from VPN status.
- Stremio restart remains independent from VPN status and validates health from inside the container.
- Pi-hole uses a stable private DNS bridge through the persistent gateway.
- Legacy `start-vpn.*` launchers remain as compatibility wrappers only.

## Configuration reliability

Version 2.0.0 explicitly protects the configuration lifecycle:

1. WebAdmin writes `/config/admin-settings.json` atomically.
2. The saved file is read back and verified.
3. WebAdmin verifies that the running Stremio container sees the same values.
4. Server restart is executed through the Docker API.
5. The restart is validated using `127.0.0.1:11470/health` inside the Stremio container.
6. The shared configuration volume remains read/write in WebAdmin and read-only in Stremio.

These guarantees apply in DIRECT, VPN CONNECTED and VPN ERROR states.

## Development and release model

2.0.0 introduces dedicated 2.x branches and workflows:

- `develop/2.x`
- `feature/*`
- `release/2.x.y`
- `hotfix/2.x.y`

- `2.x Dependency Validation`
- `2.x Release`
- Dependabot updates targeting `develop/2.x`

## Upgrade notes

Before upgrading:
- back up persistent Docker volumes;
- do not run `docker compose down -v`;
- keep the existing `stremio-config`, `stremio-cache`, `webadmin-data`, `vpn-data`, Pi-hole and Gluetun volumes.

After switching to 2.0.0, start the platform only with:

```bash
sh start.sh
```

VPN is enabled or disabled from WebAdmin. `start-vpn.sh` is retained only for backwards compatibility and launches the same unified stack.

## Breaking changes

- `compose.vpn.yaml` no longer exists.
- Direct and VPN modes no longer use different Compose topologies.
- Gluetun container lifecycle and VPN tunnel lifecycle are separate concepts.
- 2.x uses unified component version numbers.
