# Stremio Server WebAdmin 2.0.16

Browser embedded-subtitle discovery fix.

## Fixed

- Chromium/Web Player HLS playback now receives embedded subtitle renditions directly in the HLS master playlist.
- The A/V FFmpeg command remains subtitle-free, preserving the 2.0.14 muxer reliability fix and avoiding the unsupported `sname`/subtitle-only `var_stream_map` failure from 2.0.13.
- Each embedded subtitle track is advertised as an HLS `EXT-X-MEDIA:TYPE=SUBTITLES` rendition with its language and global FFmpeg stream index.
- Per-track HLS subtitle playlists point to the 2.0.15 streaming WebVTT extractor, so `track=31` remains the same identifier from discovery through extraction.
- Subtitle playlist requests count as playback activity so the HLS transcode is not reaped while subtitles are being consumed.

## Validation basis

Live 2.0.15 validation showed the browser playing HLS video correctly while the subtitle button stayed disabled and the server received no `subtitles.json`, `subtitles.vtt` or `subtitleSignature` request. This confirms that the browser HLS path requires subtitle discovery from the master manifest rather than the native subtitle API alone.
