# Stremio Server WebAdmin 3.0.13

## Summary

3.0.13 extends the VPN subsystem with Proton VPN support and makes BitTorrent inbound-port policy explicitly VPN-aware. Proton WireGuard and OpenVPN profiles can be managed from WebAdmin; Proton NAT-PMP port forwarding can publish the provider-assigned TCP/UDP port to the Core at runtime. DIRECT mode retains the normal Core UPnP/NAT-PMP policy, while VPN mode disables Core-side UPnP/NAT-PMP to prevent conflicting mappings.

## Changes

- Added Proton VPN as a managed provider in WebAdmin.
- Added Proton WireGuard configuration import and native profile support.
- Added Proton OpenVPN profile support.
- Added Proton NAT-PMP lease management and dynamic forwarded-port publication.
- The Core follows the VPN-forwarded BitTorrent port without a server restart.
- Core UPnP/NAT-PMP is disabled while VPN is active and restored to the configured DIRECT policy after VPN disconnect.
- /netcheck.json now reports VPN state, effective listen-port mode, UPnP policy and effective UPnP/NAT-PMP state.
- Active VPN profiles must be disconnected before editing, deleting or switching to another profile.
- Proton profile validation rejects incompatible Moderate NAT + NAT-PMP configurations.
- VPN runtime sanitization removes unsafe imported OpenVPN script hooks.
- GPU launch contract is unchanged: normal startup/recreate must use start.sh so the detected VAAPI/NVIDIA Compose overlay is applied.

## Upgrade notes

Use the normal documented upgrade procedure and preserve the existing .env and persistent volumes.

On GPU hosts, use sh start.sh for startup and recreate operations. Do not use a plain docker compose up --force-recreate for the server because it bypasses automatic GPU overlay selection and can recreate the runtime without the VAAPI/NVIDIA device mapping.

Existing CyberGhost profiles remain supported. Proton users should import a provider-generated WireGuard/OpenVPN configuration. For Proton port forwarding, use a configuration with NAT-PMP enabled and Moderate NAT disabled.
