# Stremio Server WebAdmin 2.0.4

## Summary

Hotfix release for the DIRECT/VPN gateway transition introduced in the 2.0.x single-Compose architecture. It restores DNS resolution for Stremio after an intentional VPN disconnect and makes the Gluetun status API accurately represent DIRECT mode.

## Components

- Fork platform: 2.0.4
- Upstream server/core: 1.6.14
- WebAdmin: 2.0.4
- VPN gateway: 2.0.4
- Upstream baseline: 1.6.14 (53efb275)

## Fixes

- Keep a stable local DNS endpoint for Stremio in DIRECT mode.
- Route DIRECT DNS as Stremio -> 127.0.0.1:53 -> Pi-hole -> gateway:1053 -> configured public resolver.
- Release 127.0.0.1:53 before Gluetun starts so VPN mode can own its encrypted local resolver without a port conflict.
- Restore the local Pi-hole DNS bridge after an explicit VPN disconnect.
- Preserve fail-closed behavior when VPN is requested but the tunnel fails.
- Report intentional DIRECT mode as stopped/direct instead of unavailable in /api/gluetun/status.
- Do not report the VPN kill switch as active when VPN is intentionally disabled.

## Regression validation

Validate the complete transition on the test server:

1. DIRECT: DNS resolution, server health and public IP.
2. VPN ON: DNS resolution, VPN public IP, kill switch and server health.
3. VPN OFF: DNS resolution returns, public IP matches direct host egress, and the gateway container is not recreated.
4. WebAdmin save/restart and persistent configuration in both modes.
5. Pi-hole upstream remains gateway:1053 in both modes.

## Upgrade notes

Preserve persistent Docker volumes. Do not use `docker compose down -v` during upgrade.
