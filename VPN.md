# VPN / CyberGhost WebAdmin integration

This fork can route only the **Stremio runtime** through CyberGhost OpenVPN using a dedicated **Gluetun** gateway while keeping WebAdmin and Pi-hole directly reachable from the LAN.

## Security model

- `stremio-libtorrent-server` shares Gluetun's network namespace in VPN mode.
- The design is **fail-closed**: if the tunnel is stopped or fails, Stremio does not fall back to the host WAN.
- WebAdmin and Pi-hole remain on the normal Docker/LAN network.
- The Gluetun control API is not published to the host and uses a private API key generated by `start-vpn.sh`.
- VPN profile secrets are stored in the private `vpn-data` Docker volume and are never returned by the WebAdmin API.
- CyberGhost does not provide VPN-side port forwarding, so VPN mode deliberately does not publish Stremio's BitTorrent port on the host.

## CyberGhost profile format

Create a manual **OpenVPN** configuration in the CyberGhost portal. Each connection imported into WebAdmin must include the downloaded ZIP with:

```text
openvpn.ovpn
ca.crt
client.crt
client.key
```

WebAdmin also accepts the values shown by CyberGhost for that router/device configuration:

- country;
- server group/hostname;
- generated OpenVPN username;
- generated OpenVPN password;
- pre-shared value, when present;
- provider-side extra-feature selections: malicious-site protection, ad blocking, tracking blocking and HTTPS redirect.

The extra-feature switches are stored as **profile metadata**. Their actual provider-side behaviour is determined by the CyberGhost configuration generated in the portal; changing those options later requires downloading/importing the regenerated ZIP.

## Connection management in WebAdmin

Open **WebAdmin → VPN**. The page supports multiple independent connections and lets you:

- **Create** a connection by importing a CyberGhost ZIP;
- **Edit** its descriptive fields and replace credentials/bundle material;
- **Activate** one connection immediately;
- **Delete** an inactive connection and its private profile files;
- mark one connection as **Enable at startup**;
- disable automatic startup selection;
- Connect / Disconnect / Reconnect the current tunnel;
- run the protection test and inspect redacted Gluetun logs.

Only one profile is active at a time and only one profile can be the startup default.

Secrets are write-only: saved username/password/pre-shared/certificate/private-key values are represented only as configured/not configured in the UI.

## First-time setup

Update/start the normal stack first:

```bash
git checkout main
git pull --ff-only origin main
sh start.sh
```

Open WebAdmin on port `8090`, go to **VPN**, click **New connection**, fill the CyberGhost values and select the downloaded ZIP. Use **Save & Activate**. If direct mode is currently running, WebAdmin prepares that profile for the next VPN start.

Then start VPN mode on the host:

```bash
sh start-vpn.sh
```

The launcher detects the LAN address, creates `.vpn-control-key` on first use, pulls the current Server/WebAdmin/VPN images and starts the full VPN stack without deleting persistent volumes.

## Startup behaviour

A profile marked **Enable at startup** is selected on a normal VPN gateway boot. A manual activation can temporarily select another profile. The gateway records the profile it actually started and keeps the configuration in `vpn-data` across container recreation and host reboot.

The VPN container itself uses `restart: unless-stopped`, so after Docker/host startup it comes back automatically when the VPN stack was the deployed mode.

## Safe OpenVPN import

WebAdmin validates the ZIP before storing it. It requires the four CyberGhost files, rejects unsafe archive paths/symlinks and creates a sanitized runtime OpenVPN file. Executable OpenVPN script/plugin/management directives are not carried into the runtime profile.

The imported `openvpn.ovpn` is the authority for protocol/server endpoint. If you explicitly choose UDP or TCP in WebAdmin, it must match the bundle.

## Switching between modes

VPN mode:

```bash
sh start-vpn.sh
```

Direct mode:

```bash
sh start.sh
```

Both launchers preserve named volumes. **Do not use `docker compose down -v`** for normal updates or mode changes.

## Protection test

The WebAdmin protection test compares direct host/WebAdmin egress, Gluetun's reported VPN address and Stremio's own public egress. A protected running result requires Stremio to use the VPN address rather than the host WAN. When the VPN is deliberately stopped, Stremio should have no public egress.

## Troubleshooting

Check containers:

```bash
VPN_CONTROL_API_KEY="$(cat .vpn-control-key)" docker compose -f compose.vpn.yaml ps
```

Check Gluetun logs:

```bash
docker logs --tail=200 stremio-gluetun
```

Confirm Stremio shares Gluetun's network namespace:

```bash
docker inspect stremio-libtorrent-server --format '{{.HostConfig.NetworkMode}}'
```

If `/dev/net/tun` is missing, enable TUN support on the Docker host before starting VPN mode.
