# Stremio Server WebAdmin 2.0.15

Embedded-subtitle reliability hotfix discovered during live 2.0.14 validation.

## Fixed

- `subtitles.json` and `subtitles.vtt` now use the same public subtitle track identifier: FFmpeg's global stream index.
- The extractor no longer interprets a listed global track such as `31` as subtitle-relative `0:s:31`; it maps the exact listed stream as `0:31`.
- Embedded WebVTT extraction is streamed directly from FFmpeg instead of buffering the complete subtitle track behind a hard 60-second `subprocess.run(..., timeout=60)` wall.
- Long movies with many embedded subtitles therefore begin returning WebVTT immediately instead of ending in an unhandled `subprocess.TimeoutExpired` HTTP 500.
- Invalid track identifiers return a controlled HTTP 404.
- Subtitle-probe timeouts return a controlled HTTP 504.
- FFmpeg child processes are terminated/reaped if the client disconnects before extraction completes.

## Validation basis

Live 2.0.14 diagnostics reproduced a 60-second `TimeoutExpired` while extracting Portuguese subtitle track 29 (global stream 31). The same FFmpeg mapping produced valid Portuguese WebVTT when allowed to stream, proving the source track itself was valid.
