## Locked optimized Pi-hole baseline

This release introduces an authoritative Pi-hole v6 baseline for the Stremio platform. The managed DNS settings are injected through Docker `FTLCONF_*` environment variables, making them read-only inside Pi-hole while the container is running and preventing accidental changes from the Pi-hole Web UI or local configuration from bypassing the platform policy.

### Locked defaults

- DNS forwarding concurrency: `300`
- DNS cache entries: `10000`
- cache optimizer: `3600` seconds
- blocked upstream TTL: `86400` seconds
- domain-needed: enabled
- bogus-private filtering: enabled
- DNSSEC: disabled
- query logging: enabled
- rate limit: `1000` queries per `60` seconds
- blocking: enabled
- blocking mode: `NULL`
- query database retention: `30` days
- database write interval: `60` seconds
- SQLite WAL: enabled

The baseline is intentionally conservative for streaming workloads: it improves cache efficiency and burst tolerance while keeping RAM and persistent database growth bounded.

## VPN DNS policy

VPN mode locks the Pi-hole upstream to the private Gluetun DNS bridge:

```text
172.30.0.10#1053
```

The DNS path is therefore:

```text
Stremio
  ↓
Pi-hole
  ↓
Gluetun DNS Bridge
  ↓
Gluetun Secure Resolver
  ↓
CyberGhost VPN tunnel
```

This prevents a routine Pi-hole configuration change from redirecting VPN-mode DNS directly to a public resolver outside the intended Gluetun path.

## Direct mode

Direct mode keeps the external Pi-hole upstream configurable, with Cloudflare as the default:

```text
1.1.1.1
1.0.0.1
```
