# Stremio Server WebAdmin v2.0.9

## Release summary

Version 2.0.9 fixes a DNS proxy race during VPN DIRECT/VPN state transitions.

The release keeps the integrated upstream server/core at 1.6.15 while advancing the fork platform, WebAdmin and VPN gateway to 2.0.9.

## VPN and DNS

- Remove stale Stremio-managed `socat` DNS proxy processes before changing DNS ownership.
- Ensure VPN mode releases the DIRECT-mode local Pi-hole proxy before Gluetun starts its DNS resolver.
- Prevent stale `:53` and `:1053` listeners from causing Gluetun DNS startup failures.
- Preserve the intended DIRECT-mode DNS path through Pi-hole.
- Preserve the VPN-mode DNS path through Gluetun and the VPN tunnel.
- Validate repeated DIRECT → VPN → DIRECT → VPN transitions.

## Validation

The 2.0.9 change was validated against the following runtime states:

- VPN ON with Gluetun DNS reported as running.
- Pi-hole queries through `172.30.0.10:1053`.
- Stremio DNS resolution through `127.0.0.1:53`.
- VPN public IP `146.70.59.176` during the tested CyberGhost profile.
- VPN kill switch active while VPN is enabled.
- VPN OFF returning to direct public egress.
- Second VPN ON without the previous `address already in use` DNS failure.
- Stremio health remaining healthy after transitions.
- Routing through `tun0` verified with `ip route get 1.1.1.1`.

A transient OpenVPN `RTNETLINK answers: File exists` route-add message was observed during one reconnect, but the VPN completed initialization and the resulting routing table was correct.

Persistent Docker volumes must be preserved during upgrade. Do not use `docker compose down -v`.
