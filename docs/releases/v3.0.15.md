# Stremio WebAdmin 3.0.15 — Gateway BT port integration

## Summary

Introduces an opt-in host-level integration with VPN Gateway Multi.
The Gateway bootstrap installs a read-only observer; Stremio's
existing reconciler consumes its verified, fresh, owner-scoped port observation
and updates `STREMIOSRV_BT_LISTEN_PORT` only when the port differs.

## Components

- Fork / WebAdmin: 3.0.15
- Integrated core: 1.6.34 (unchanged)
- Port-forward source: VPN Gateway Multi 1.0.5

## Deployment compatibility

This integration targets **standalone Stremio Docker Compose deployments**
where `stremio-libtorrent-server` owns published TCP and UDP ports.
The consumer refuses automatic recreation when Stremio uses a shared
Gluetun `network_mode: container:...`; this mode retains its existing
VPN-native port management. The feature is disabled by default.

The Gateway HTTPS port-status service requires a separately provisioned
read-only bearer token and verified CA. Never embed the token in the
public bootstrap or a deployment package.

For a compatible standalone deployment, install and enable
`systemd/stremio-webadmin-reconcile.timer` with a service working
directory adjusted to the actual Compose location. The Gateway bootstrap
configures `/etc/stremio-webadmin/port-sync.conf` using
`SOURCE=observation` and validates host MAC and policy ownership.
The observer updates only a root-protected JSON file. Stremio remains
the only writer of `.env` and the only recreator of its server container.

## Safety

The consumer validates MAC/IP/gateway, freshness, lease expiration and
TCP/UDP symmetry. Missing or stale observations do not change the port.
A changed port is applied through the GPU-aware `start.sh`, validated
using Docker bindings and health, and reverted on failure.
No database or persistent media cache is deleted.
