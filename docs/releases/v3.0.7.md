# Stremio Server WebAdmin 3.0.7

## Summary

Version 3.0.7 is a corrective Web Player and WebAdmin release focused on
browser HLS playback stability.

The release fixes three related areas discovered during real browser playback
validation:

- single-track browser HLS now uses a deterministic application-owned
  `master.m3u8` while FFmpeg continues to generate the fMP4 media playlist,
  initialization segment and media segments;
- subtitle URLs now preserve and support the implicit `fileIdx=-1` contract
  used by Stremio when no explicit file index is supplied, including the
  WebVTT route used by HLS subtitles;
- WebAdmin playback detection now falls back to active transcoding/stream
  state when the playback registry is available but contains no correlated
  playback entry.

The integrated Stremio Server/Core baseline remains 1.6.22.

## Components

- Fork platform: 3.0.7
- WebAdmin: 3.0.7
- Integrated server/core: 1.6.22
- VPN gateway: 3.0.6 (unchanged)

The VPN component has no functional change in this release and therefore
remains on the previously validated 3.0.6 image.

## Web Player HLS

Single-track HLS no longer relies on FFmpeg to generate a master playlist
without a variant stream map.

For single-track playback:

- the application publishes `master.m3u8`;
- `master.m3u8` references `index.m3u8`;
- FFmpeg owns `index.m3u8`, `init.mp4` and the `.m4s` media segments;
- the media path remains fMP4;
- multi-track HLS continues to use FFmpeg `-var_stream_map` and
  `-master_pl_name`.

This prevents a header-only master playlist from being exposed to the Web
Player while preserving the validated fMP4 architecture.

## Subtitle fileIdx=-1 handling

Stremio may use `-1` when no explicit torrent file index was supplied.

Version 3.0.7 preserves that public contract throughout the subtitle pipeline:

- stream URL parsing accepts the signed `-1` file index;
- HLS subtitle playlists retain `/<infoHash>/-1/subtitles.vtt`;
- a literal `/{info_hash}/-1/subtitles.vtt` route is provided because the
  normal Starlette `{idx:int}` converter does not match a negative value;
- the existing media resolution path continues to resolve the implicit file
  selection.

Regression coverage verifies both URL generation and HTTP delegation through
the literal `-1` WebVTT route.

## WebAdmin playback detection

WebAdmin no longer treats an empty playback registry as proof that an active
stream is only downloading.

When the registry contains correlated playback activity it remains
authoritative. When it contains no correlation, WebAdmin falls back to the
existing transcoding and active-stream information.

Regression tests cover empty-registry fallback, correlated registry activity
and multiple active streams.

## Validation

The release candidate was validated on the DEV environment before release
preparation.

Validated runtime state includes:

- Web Player playback with subtitles enabled without the previously observed
  freeze;
- playback continued beyond the initial playback window;
- seek operation remained functional;
- single-track HLS remained fMP4;
- subtitle HLS and WebVTT requests using `fileIdx=-1` returned successfully;
- VAAPI remained available through `/dev/dri/renderD128`;
- H.264 VAAPI and HEVC VAAPI runtime readiness remained available;
- Server/Core remained 1.6.22;
- Server and WebAdmin remained healthy after the TEST8 cutover.

Dedicated regression gates completed successfully during development,
including subtitle, HLS and WebAdmin playback-detection coverage.

Fast CI, Full regression, integration tests, release image smoke tests and
deployment-package validation remain mandatory before public publication.

## Upgrade notes

No persistent-state migration is required for 3.0.7.

No new mandatory environment variable is introduced by the Web Player,
subtitle or playback-detection fixes.

Existing configuration, cache, Library state, VPN configuration and WebAdmin
persistent settings must be preserved during upgrade.

On GPU hosts, use `start.sh` for Compose lifecycle operations so GPU discovery
and the appropriate VAAPI/NVIDIA overlay are applied. Do not replace the
supported launcher with a plain `docker compose up` when recreating the
Server container.

Do not use `docker compose down -v` during a routine upgrade because it removes
named volumes.

The VPN Gateway is unchanged from 3.0.6 and does not require recreation solely
for the 3.0.7 Server/WebAdmin corrective release.
