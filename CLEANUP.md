# Production Package Cleanup — 2.0.17

This review separates repository source, local deployment state and generated development artefacts.

## Removed from the distributable package

- `.env` and `.env.backup-*` — local/server-specific configuration;
- `.pytest_cache/` — generated test cache;
- `.venv-test/` and `.venv-test312/` — local Python virtual environments;
- every `__pycache__/`, `*.pyc` and `*.pyo` — generated bytecode;
- `.git/` is excluded from the clean ZIP artifact (the working source may still be used as a Git checkout).

## Kept intentionally

- `start-vpn.sh`, `start-vpn.ps1`, `start-vpn.bat` — compatibility wrappers still referenced by tests/documentation;
- `compose.hub.yaml` — legacy/runtime-only deployment path still referenced by repository guard/history;
- `tests/`, `tools/`, `docs/` — source repository assets, not runtime state;
- old release notes under `docs/releases/` — project history.

## Generic configuration corrections

The generic `.env.example` no longer assumes:

- a fixed `192.168.1.245` host address;
- a specific Stremio account/allowlist;
- `/dev/dri/renderD129`;
- Intel `iHD` on every host;
- Angola as the universal timezone;
- aggressive transcoding garbage-collection values;
- VAAPI as the only safe baseline.

The default deployment is CPU-safe. `start.sh` may promote the runtime to VAAPI/NVIDIA only after local capability detection.

## Upgrade rule

`.env` is installation state, not a release file. During an upgrade it must be preserved and reconciled against the new `.env.example`; it must not be replaced blindly.


## Source tree vs production deployment

The Git repository remains the engineering source of truth and therefore keeps tests, CI workflows, source code and release tooling. Production releases now generate a separate minimal deployment ZIP/TAR with only the files required to install, configure, back up and operate published images. Production hosts should prefer that release artefact instead of cloning the full repository.
