# Stremio Server WebAdmin 3.0.8

## Summary

Version 3.0.8 integrates the Stremio Server/Core 1.6.23 Web Player loader
correction and adds host-filesystem protection for ordinary Library downloads.

The Web Player now preserves a streaming-server URL selected manually by the
user. The deployment seed URL is applied on first use, when the Web Player is
still using its own localhost default, or when the deployment seed itself
changes. A manually selected server is no longer overwritten periodically.

Ordinary Library downloads now use a server-side disk admission policy before
the torrent is added. By default the host keeps the greater of 10 GiB or 10%
of the filesystem free. Existing committed download bytes and the candidate
download size are included in the decision.

The existing Keep/Pin policy remains independent and unchanged.

This release also hardens incomplete-torrent HLS playback, synchronizes dynamic embedded
subtitles with the transcoded HLS timeline, adds account-aware My Library synchronization in the
bundled Web Player, and hides libtorrent housekeeping files from the playable cache list while
still accounting for their disk usage.

## Components

- Fork platform: 3.0.8
- WebAdmin: 3.0.8
- Integrated server/core: 1.6.23
- VPN gateway: 3.0.6 (unchanged)

The Server/Core integration retains the fork-owned WebAdmin entrypoint,
FFmpeg policy wrapper, Continue Watching integration, VPN topology and Library
behaviour while incorporating the upstream 1.6.23 Web Player loader fix.

## Web Player server URL persistence

The Web Player loader no longer forces the deployment streaming-server URL
over a server selected manually in Web Player settings.

The seed URL is still used when appropriate for a new deployment and is added
to the saved server list without replacing the user's manually selected
server.

The generated loader is installed into the Web Player build during the Server
image build. Its browser asset is served with a no-cache policy so a release
update is not indefinitely hidden by browser or service-worker caching.

## Host disk reserve

Ordinary Library downloads now enforce a host-filesystem reserve before
calling the torrent engine.

The default configuration is:

```env
STREMIOSRV_HOST_MIN_FREE_GB=10
STREMIOSRV_HOST_MIN_FREE_PERCENT=10
```

The effective reserve is the maximum of:

- the configured minimum free GiB;
- the configured minimum free percentage;
- the existing 2 GiB operational minimum;
- the existing 2% operational minimum.

For a download with a known candidate size, admission requires:

```text
disk_free - committed - candidate_size >= reserve
```

For an unknown candidate size, the same policy is applied with a candidate
size of zero.

When the request would enter the reserve, the API returns HTTP 409 with the
`insufficient_space` contract before the torrent is added.

The browser uses the reserve calculated by the server rather than maintaining
a second copy of the 10 GiB / 10% policy.

Keep/Pin continues to use its existing stricter cache-budget/headroom rule.

## Incomplete torrent playback

Internal FFmpeg/Lavf source reads now keep waiting across temporary missing-piece timeouts instead
of turning torrent starvation into a premature HTTP EOF. Incomplete torrent transcoding remains
real-time paced with `-re`; completed cached media is not unnecessarily paced.

## Embedded subtitle synchronization

Embedded subtitle tracks are discovered dynamically, including language/title/forced/hearing-
impaired metadata. WebVTT windows use the actual HLS MPEG-TS start timestamp, and bounded private
reader windows prevent subtitle extraction from blocking indefinitely on unavailable torrent data.

## My Library account synchronization

The bundled Web Player checks My Library when a Stremio account authenticates. It first reads the
account addon collection, leaves unrelated addons unchanged, avoids duplicates, and replaces a
stale My Library URL/token with the canonical URL for this server. Logging out and authenticating a
different account triggers a new account-specific check.

`STREMIOSRV_LIBRARY_OWNER` is optional. When empty, every valid account authenticated in the local
Web Player follows this flow. When configured with a Stremio account `_id` or email, only that
account is allowed to receive/update My Library; other accounts are rejected before their addon
collection is read. The My Library addon token remains in persistent Library state and therefore
survives normal image rebuilds/recreates/upgrades.

## Cache list housekeeping

Libtorrent `.<infohash>.parts` and other hidden top-level housekeeping artefacts are not exposed by
`/cache.json` as playable titles. They remain on disk as required and remain included in cache
pressure/accounting and coordinated eviction.

## Upgrade notes

No persistent-state migration is required for 3.0.8.

Two optional environment variables are introduced:

```env
STREMIOSRV_HOST_MIN_FREE_GB=10
STREMIOSRV_HOST_MIN_FREE_PERCENT=10
```

Compose provides the same defaults when the variables are absent, so an
existing `.env` does not need to be modified before upgrade unless different
reserve values are desired.

Existing configuration, cache, Library state, VPN configuration and WebAdmin
persistent settings must be preserved during upgrade.

The VPN Gateway has no functional change in this release and remains on the
3.0.6 image.

On GPU hosts, use `start.sh` for lifecycle operations so GPU detection and the
appropriate VAAPI/NVIDIA Compose overlay remain active.

Do not use `docker compose down -v` during a routine upgrade because it removes
named volumes.
