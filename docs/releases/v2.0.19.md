# Stremio Server WebAdmin 2.0.19

## Summary

GPU discovery and hardware-transcoding reliability release. The integrated Stremio/libtorrent core remains 1.6.15. This release separates accelerator discovery from runtime profile selection, supports dual Intel/DRM + NVIDIA hosts, removes the fixed VAAPI render-node assumption, and improves NVIDIA/NVENC diagnostics for legacy drivers.

## Components

- Fork platform: 2.0.19
- WebAdmin: 2.0.19
- VPN gateway: 2.0.19
- Integrated server/core: 1.6.15

## Changes

- `GPU_BACKEND=auto` discovers VAAPI and NVIDIA independently.
- Dual-GPU hosts may expose both accelerator families to the Stremio container.
- VAAPI-only hosts do not require the NVIDIA runtime.
- NVIDIA-only hosts do not require a DRM render node.
- `start.sh` enumerates `/dev/dri/renderD*` instead of assuming `/dev/dri/renderD128`.
- Launcher discovery no longer depends on FFmpeg being installed on the Docker host.
- Real FFmpeg validation remains inside the running Stremio container and determines which WebAdmin profiles are selectable.
- Direct use of `compose.vaapi.yaml` requires an explicit `VAAPI_DEVICE`.
- Blank `LIBVA_DRIVER_NAME` is omitted so libva can auto-detect the driver; explicit overrides such as `iHD` remain supported.
- WebAdmin reports NVIDIA hardware detection, runtime readiness and NVENC API compatibility separately.
- NVENC API mismatches now report required and available API versions instead of incorrectly presenting the GPU as undetected.
- Added regression coverage for multiple render nodes, dual-GPU capability reporting, explicit VAAPI device policy and legacy NVENC API incompatibility.

## Physical validation

Clean-install validation was performed on a dual-GPU host with:

- Intel DRM render node: `/dev/dri/renderD129`
- NVIDIA GPU: GeForce 920M
- NVIDIA driver: `470.256.02`
- VAAPI H.264 and HEVC profiles verified successfully with the Intel iHD driver.
- Both Intel DRM and NVIDIA devices were exposed concurrently to the Stremio container.
- NVIDIA runtime and `nvidia-smi` were operational in-container.
- NVENC self-test correctly identified a compatibility mismatch: FFmpeg required NVENC API 12.0 while the legacy driver exposed 11.1.
- NVIDIA profiles remained non-selectable while VAAPI and CPU profiles remained available.

## Upgrade notes

1. Run `sh scripts/backup-before-upgrade.sh`.
2. Preserve the existing `.env` and Docker named volumes.
3. Extract the 2.0.19 deployment package over the existing installation directory.
4. Run `sh scripts/check-env-upgrade.sh`.
5. Existing `.env` files remain compatible. Review `VAAPI_DEVICE` and `LIBVA_DRIVER_NAME` only if they were previously set as host-specific overrides.
6. Run `sh start.sh config` and verify the detected GPU topology.
7. Run `sh start.sh` to reconcile the stack.
8. In WebAdmin, use **Re-test hardware** and confirm only runtime-verified profiles are selectable.
9. Do not use `docker compose down -v` during a routine upgrade.

For direct Compose use with `compose.vaapi.yaml`, `VAAPI_DEVICE` is now mandatory. Normal `start.sh` usage discovers and exports the render node automatically.
