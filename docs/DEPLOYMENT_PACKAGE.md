# Deployment package

The Git repository is the development source tree. Production installation should use the generated deployment package attached to a release.

The package intentionally contains only files required to deploy, configure, operate and upgrade the published Docker images:

- `.env.example`
- `compose.yaml`, `compose.dns.yaml`, `compose.vaapi.yaml`, `compose.gpu.yaml`
- `start.sh`, `start.ps1`, `start.bat`
- `scripts/backup-before-upgrade.sh`
- `README.md`, `QUICKSTART.md`, `VPN.md`, `WINDOWS.md`, `LICENSE`
- `FORK_VERSION`, `SERVER_VERSION`
- release notes for the packaged version

It intentionally excludes source code, tests, CI workflows, local virtual environments, cache files, development tools and legacy compatibility launchers.

The package is generated by `tools/release/build_deployment_package.py` and validated during Full regression and Release.
