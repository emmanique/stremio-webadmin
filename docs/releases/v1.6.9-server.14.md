## Trusted LAN HTTPS in VPN mode

This release decouples the trusted `stremio.rocks` certificate from VPN readiness.

Before the VPN stack starts, `start-vpn.sh` now runs a one-shot `cert-bootstrap` helper outside the Gluetun tunnel. The helper obtains or refreshes the trusted certificate and stores it in the persistent Stremio cache volume. The Stremio runtime then reuses that certificate on LAN HTTPS port `12470` instead of depending on the VPN/DNS tunnel being ready during startup.

The VPN stack refuses to start when no valid trusted certificate can be prepared, because local Stremio clients require trusted HTTPS to connect reliably.

## VPN/DNS behavior

- Application traffic remains fail-closed behind Gluetun.
- Stremio DNS remains `Stremio -> Pi-hole -> Gluetun DNS -> VPN`.
- The certificate bootstrap is the only VPN-mode helper allowed to use direct WAN egress, solely for certificate acquisition/renewal.
- Existing valid trusted certificates are reused from the persistent cache.
- Failed certificate downloads no longer trigger an unconditional copy of a missing `certificates.pem` file.
