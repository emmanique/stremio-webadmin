# Stremio Server WebAdmin 3.0.4

## Summary

3.0.4 closes the playback-continuity and runtime-observability work validated on
the DEV environment. It keeps Stremio Core authoritative for playback position and
uses Core's existing player deep link for Continue Watching when the exact prior
stream is still available.

The centre Play action on a Continue Watching card resumes through the same Core
player path as the menu Play action. Poster/details navigation is deliberately left
unchanged and continues to open the normal streams/source-selection flow.

The release also consolidates playback-session telemetry, WebAdmin direct-stream
versus transcode correlation, FFmpeg policy hardening, and Library Addon last-source
learning/order.

## Playback continuity

Stremio Core remains the source of truth for resume position. No parallel playback
progress database is introduced.

When Core exposes a `deepLinks.player` for a Continue Watching item, both menu Play
and centre Play use that existing player route. The route contains Core's exact
stream context and resume position. If Core does not expose a player route, the
normal details/source-selection path remains available.

The Library Addon records `lastSourceAt` for successfully correlated local sources
and prefers the most recently observed matching source. This is local-addon ordering;
it does not globally reorder third-party addons such as Torrentio.

## Runtime observability and transcoding

Playback-session telemetry is correlated with active source and FFmpeg workloads so
WebAdmin can distinguish logical concurrent playbacks, Direct Stream/copy, and active
transcoding more accurately. Seek generations are consolidated rather than reported
as separate logical viewers.

FFmpeg policy handling is hardened so unsafe copied-video cases can be promoted to
the required transcode path while preserving AUTO policy. GPU detection remains a
capability decision and does not itself force transcoding.

## Upgrade notes

Back up the installation state first and preserve the existing `.env` and named
Docker volumes. Extract the 3.0.4 deployment package over the installation directory,
then run:

```bash
sh scripts/check-env-upgrade.sh
sh start.sh config
sh start.sh pull
sh start.sh up -d --force-recreate
```

On GPU hosts, always run Compose operations through `start.sh`. The launcher detects
the available accelerator and adds `compose.vaapi.yaml` and/or `compose.gpu.yaml`.
Running plain `docker compose up -d --force-recreate` can bypass that selection and
recreate the Stremio container without `/dev/dri` or the NVIDIA runtime.

For VAAPI, verify after the upgrade:

```bash
docker inspect stremio-libtorrent-server --format '{{json .HostConfig.Devices}}'
docker exec stremio-libtorrent-server sh -c 'ls -l /dev/dri && test -e /dev/dri/renderD128'
```

Do not use `docker compose down -v` during the upgrade. It removes named volumes and
is not part of the supported update procedure.
