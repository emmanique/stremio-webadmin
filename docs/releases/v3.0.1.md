# Stremio Server WebAdmin 3.0.1

## Summary

3.0.1 is a patch release for Intel VAAPI driver selection. On Linux the Intel Media Driver module is named `iHD_drv_video.so`. An inherited or legacy `LIBVA_DRIVER_NAME=ihd` override is therefore not equivalent: libva searches for `ihd_drv_video.so` and VAAPI initialization fails.

The launcher now canonicalizes the Intel driver name to `iHD` before Compose starts the runtime. Empty `LIBVA_DRIVER_NAME` remains supported and continues to use libva autodetection.

## Fix

- Canonicalize inherited/legacy `LIBVA_DRIVER_NAME=ihd` to the case-sensitive Intel Media Driver name `iHD`.
- Preserve the empty-driver path so libva can auto-detect the installed driver.
- Add regression coverage that guards the Intel driver capitalization in `start.sh`.

## Validation evidence

Production upgrade validation on Intel Iris Xe with `/dev/dri/renderD128` confirmed:

- the render node is correctly mapped into the server container;
- libva autodetection opens `iHD_drv_video.so`;
- explicit `LIBVA_DRIVER_NAME=iHD` opens the same driver;
- H.264 VAAPI encode passes with the bundled real FFmpeg;
- HEVC VAAPI encode passes with the bundled real FFmpeg;
- the failure is reproduced only with the lowercase `ihd` override.

## Upgrade notes

Preserve the existing `.env` and named Docker volumes. After the coordinated 3.0.1 images and deployment package are published, pin Server, WebAdmin and VPN to `:3.0.1`, validate with `sh start.sh config`, then pull and recreate the stack.

Existing installations that contain `LIBVA_DRIVER_NAME=ihd` do not need to retain that lowercase value; 3.0.1 canonicalizes it at launcher runtime. Leaving the variable unset remains the preferred portable baseline unless the host requires an explicit driver override.

Never use `docker compose down -v` for this patch upgrade.
