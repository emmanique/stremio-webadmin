# Stremio Server WebAdmin 3.0.5

## Summary

3.0.5 integrates the functional server fixes from upstream 1.6.21/1.6.22 into the
3.0.x platform without replacing the fork's custom proxy, transcoding, VPN, Library,
or WebAdmin behavior.

The release wires the existing UPnP setting into the libtorrent engine, rejects HLS
playlists that terminate before their declared Content-Length, aligns the platform
runtime with Server/Core 1.6.22, and adds regression coverage for truncated
playlists in both the normal proxy path and the external mediaURL reader.

## Components

- Platform/Fork: 3.0.5
- WebAdmin: 3.0.5
- VPN Gateway coordinated image: 3.0.5
- Upstream Server/Core: 1.6.22

## Upstream 1.6.22 integration

The integration is selective rather than a blind upstream sync so the fork's
existing platform behavior remains intact.

- `STREMIOSRV_ENABLE_UPNP` now reaches the torrent Engine.
- When UPnP is disabled, libtorrent disables both UPnP and NAT-PMP port mapping.
- DHT and LSD behavior is unchanged.
- Playlist responses whose declared Content-Length is not fully delivered are
  rejected with HTTP 502 and `truncated playlist`.
- The truncation protection applies to both `/proxy` playlist handling and the
  guarded external `mediaURL` reader used by the HLS/transcoding path.
- Server package metadata and WebAdmin runtime target are aligned to 1.6.22.

## Regression coverage

Dedicated regression tests cover short playlist responses in both affected paths.
The dependency lock and development dependencies are aligned with the test surface
used by WebAdmin and the server.

The complete deterministic/full repository regression remains mandatory in GitHub
Actions before merge/publication.

## Validation

The final 3.0.5 candidate was validated on the DEV environment before release
preparation. The six runtime regression areas passed:

1. VPN OFF -> DIRECT -> VPN ON, including routing restoration.
2. Proxy/HLS behavior, including exact truncated-playlist rejection.
3. Real playback and HLS transcoding, including HDR-to-SDR VAAPI operation.
4. My Library Pin/Unpin behavior and persistence semantics.
5. External `mediaURL` resolution, probe and HLS master generation.
6. WebAdmin SAVE + RESTART, configuration persistence, container restart and
   restoration of the original setting.

Additional validated runtime state:

- Server health: `healthy`
- Server/Core version: 1.6.22
- VAAPI render node: `/dev/dri/renderD128`
- H.264 VAAPI: available
- HEVC VAAPI: available
- Real FFmpeg runtime: `/usr/local/libexec/stremio/ffmpeg-real`
- SAVE + RESTART retained Server 1.6.22 and VAAPI availability after recreation
- External mediaURL test returned a valid H.264/AAC probe and generated an HLS
  master successfully
- My Library Unpin removed pin state without deleting the cached media

The release remains subject to Fast CI, Full regression and the release workflow's
own full regression before publication.

## Upgrade notes

Back up the installation state first and preserve the existing `.env` and named
Docker volumes. Extract the 3.0.5 deployment package over the installation directory,
then run:

```bash
sh scripts/check-env-upgrade.sh
sh start.sh config
sh start.sh pull
sh start.sh up -d --force-recreate
```

On GPU hosts, run Compose operations through `start.sh`. The launcher detects the
available accelerator and applies the required VAAPI/NVIDIA overlay. Running plain
`docker compose up -d --force-recreate` can bypass GPU discovery and recreate the
server without the required device mapping.

For VAAPI, verify after upgrade:

```bash
docker inspect stremio-libtorrent-server --format '{{json .HostConfig.Devices}}'
docker exec stremio-libtorrent-server sh -c 'ls -l /dev/dri'
curl -fsS http://HOST-IP:8090/api/transcoding/status | python3 -m json.tool
```

Do not use `docker compose down -v` during a routine upgrade. It removes named
volumes and is not part of the supported update procedure.
