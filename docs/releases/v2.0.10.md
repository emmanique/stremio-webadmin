# Stremio Server WebAdmin v2.0.10

## VPN readiness and DNS convergence

Version 2.0.10 improves VPN connection and reconnection readiness validation.

The release prevents the WebAdmin from reporting a successful VPN connection before the complete DNS path is actually usable.

The integrated upstream server/core remains at version 1.6.15.

## Changes

### VPN readiness

VPN connect and reconnect operations now wait for:

- Gluetun VPN status to be `running`.
- Gluetun DNS status to be `running`.
- A successful real DNS query through the Pi-hole -> Gluetun DNS proxy path.
- Stremio local health to remain available inside the shared Gluetun network namespace.

The DNS readiness probe validates:

`Pi-hole -> 172.30.0.10:1053 -> Gluetun DNS -> upstream resolver`

This prevents a transient state where the Gluetun Control API reports DNS as running while the local DNS resolver is not yet ready to accept queries.

### Failure handling

If the VPN or DNS path does not become ready within the readiness timeout:

- `/api/vpn/connect` returns HTTP 503.
- `/api/vpn/reconnect` returns HTTP 503.
- The failure reason is recorded in the VPN audit log.
- A successful HTTP 200 response now means the VPN and DNS path have completed readiness validation.

## Validation

The release candidate was validated with:

- VPN reconnect from an active VPN session.
- VPN OFF -> ON transition.
- Immediate DNS resolution through `172.30.0.10:1053` after the API returned HTTP 200.
- Pi-hole upstream through the Gluetun DNS proxy.
- Stremio resolver on `127.0.0.1`.
- Stremio Internet routing through `tun0`.
- VPN public IP validation.
- Kill-switch and fail-closed routing validation.
- Stremio Core health validation.
- Full automated regression suite.

Final automated regression result:

- 1141 tests passed.
- 2 tests skipped.
- 2 non-blocking dependency deprecation warnings.
