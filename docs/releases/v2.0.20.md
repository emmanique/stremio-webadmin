# Stremio Server WebAdmin 2.0.20

## Summary

Patch release following 2.0.19. It fixes clean-install VAAPI environment handling, reports the effective VAAPI render node consistently in WebAdmin, and normalizes VPN provider telemetry to the active CyberGhost profile. The integrated Stremio/libtorrent core remains 1.6.15.

## Components

- Fork platform: 2.0.20
- WebAdmin: 2.0.20
- VPN gateway: 2.0.20
- Integrated server/core: 1.6.15

## Changes

- Clean installs no longer seed an active blank `LIBVA_DRIVER_NAME=` entry.
- The launcher removes only empty legacy `LIBVA_DRIVER_NAME=` assignments while preserving explicit non-empty overrides such as `iHD`.
- VAAPI discovery remains dynamic and supports render nodes such as `/dev/dri/renderD129`.
- `compose.vaapi.yaml` now exposes the detected `VAAPI_DEVICE` to WebAdmin as well as the streaming server.
- WebAdmin no longer reports a fixed `/dev/dri/renderD128` default when the runtime is using another render node.
- VPN status/config telemetry now derives the provider from the active profile, avoiding stale `pia` or `custom` labels when a CyberGhost profile is active.
- Regression coverage was added for blank LIBVA handling, effective VAAPI device reporting, and active-profile VPN provider normalization.

## Physical validation

Clean-install validation on the dual-GPU test host confirmed:

- Server/core 1.6.15 and WebAdmin 2.0.19 runtime baseline healthy before the patch release.
- Intel VAAPI exposed at `/dev/dri/renderD129`.
- NVIDIA runtime exposed concurrently.
- VAAPI H.264, HEVC, Full H.264 and Full HEVC runtime self-tests passed.
- NVENC remained correctly unavailable on the legacy NVIDIA driver because FFmpeg requires NVENC API 12.0 while the driver exposes 11.1.
- Configuration write, persistence and server restart all passed.
- DIRECT -> VPN -> DIRECT routing passed with the Gluetun namespace remaining stable.
- VPN ON produced a different public IP from the host and enabled kill-switch/fail-closed behavior.
- VPN OFF removed `tun0`, restored the host public IP, and preserved configuration.

## Upgrade notes

1. Run `sh scripts/backup-before-upgrade.sh`.
2. Preserve the existing `.env` and Docker named volumes.
3. Extract the 2.0.20 deployment package over the existing installation directory.
4. Run `sh scripts/check-env-upgrade.sh`.
5. If the local `.env` contains an empty active `LIBVA_DRIVER_NAME=` line, the launcher normalizes it automatically.
6. Keep an explicit non-empty `LIBVA_DRIVER_NAME` only when the host actually requires a driver override.
7. Run `sh start.sh config` and verify the detected VAAPI device.
8. Run `sh start.sh` to reconcile the stack.
9. Validate WebAdmin configuration save/restart, transcoding profiles, and VPN DIRECT -> ON -> OFF behavior.
10. Do not use `docker compose down -v` during a routine upgrade.
