# Stremio Server WebAdmin 2.0.14

Reliability hotfix for WebAdmin actions and HLS multi-audio playback.

## Fixed

- WebAdmin `Save configuration` and `Restart server` actions are hardened with explicit button types, visible progress/failure feedback and guaranteed re-enable in `finally` blocks.
- The WebAdmin root page is now served with `Cache-Control: no-store` and `Pragma: no-cache` so an older inline JavaScript action handler cannot survive an image upgrade.
- 2.0.13's HLS subtitle rendition packaging is removed after a real FFmpeg failure reproduced `Invalid keyval sname` / header initialization errors.
- Alternate audio tracks remain exposed through a validated HLS `agroup` master playlist.
- Embedded subtitles continue through the existing Stremio-native `/subtitles.json` and `/subtitles.vtt` routes instead of being forced into unsupported subtitle-only HLS variants.
- The validated VAAPI behavior remains unchanged.

## New release gates

- A real FFmpeg smoke test builds a tiny multi-audio source, executes the generated HLS command and requires an actual `master.m3u8` with two `EXT-X-MEDIA:TYPE=AUDIO` renditions.
- Browser-action JavaScript is executed under Node with a fake DOM to prove that clicking the WebAdmin save/restart handlers issues `PUT /api/config` and `POST /api/restart` and restores button state.
- Static checks also require explicit `type="button"` wiring for both actions.

## Upgrade

```bash
cd ~/stremio-libtorrent-server-webadmin
git fetch --prune origin
git checkout main
git pull --ff-only origin main
docker compose pull
sh start.sh
```

Do not use `docker compose down -v`.
